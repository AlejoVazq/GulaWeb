# Fase 2 — Carta: Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modelo de carta multi-local con API de edición y lectura pública, fotos optimizadas, una carta de demostración cargable por CLI y la app web `apps/carta` donde el cliente navega la carta y arma su carrito.

**Architecture:** Las reglas puras de precios y selección de opciones viven en `@gula/shared` (las usan la carta, la API al recalcular pedidos en la fase 4 y la PC). La API suma tablas con `local_id` + RLS y columnas `actualizado_en`/`eliminado_en` para la sincronización de la fase 3. `apps/carta` es una SPA React + Vite servida como estáticos por Caddy, que consume `GET /api/publico/locales/:slug/carta`.

**Tech Stack:** lo de la fase 1 + `@fastify/multipart`, `sharp`, Vite 6, React 19, react-router 7, @testing-library/react, jsdom.

**Spec:** `docs/superpowers/specs/2026-11-18-gulaweb-design.md` (§8 Categoría/Producto/GrupoOpciones/Sector, §9, §14 Carta). Base: fase 1 (`docs/superpowers/plans/2026-11-18-01-base-servidor.md`).

## Global Constraints

- Todas las de la fase 1.
- Dinero en **centavos enteros** (`precio: 250000` = $ 2.500). Formato visible: `$ 2.500` (sin decimales si son ,00; si no, `$ 2.500,50`), separador de miles `.`.
- Toda tabla nueva: `local_id` + política `aislamiento_local` + `actualizado_en timestamptz not null default now()` (se actualiza en cada UPDATE) + `eliminado_en timestamptz null` (borrado lógico; la API nunca borra filas de carta).
- La estética queda para la fase 10: en esta fase la carta usa estilos mínimos y legibles con tokens CSS (`--color-*`, `--espacio-*`), mobile-first, sin librería de componentes.
- Horarios de categoría se evalúan en `America/Argentina/Buenos_Aires`.

## Review Focus

1. **Producto con grupo obligatorio sin elegir** → `validarSeleccion` lo rechaza con el nombre del grupo; el botón "Agregar" de la carta queda deshabilitado. → tests en Task 1 y Task 10.
2. **Producto o categoría borrados/ocultos o de otro local** → nunca aparecen en la carta pública. → test en Task 6.
3. **Categoría con horario que cruza medianoche** (ej. 20:00–02:00) → a las 01:00 está en horario. → test en Task 6.
4. **Foto enorme o que no es imagen** → >8 MB responde 413 `ARCHIVO_GRANDE`; no-imagen responde 400 `IMAGEN_INVALIDA`; nunca se guarda el original. → test en Task 7.
5. **Slug inexistente** → la carta pública responde 404 y la app muestra "No encontramos este local". → tests en Task 6 y Task 9.

### Task 1: Dinero y reglas de la carta en shared

**Files:** Create `packages/shared/src/dinero.ts`, `packages/shared/src/carta.ts` · Test: `dinero.test.ts`, `carta.test.ts`

**Interfaces — Produces:**
- `formatearPrecio(centavos: number): string`
- Tipos: `OpcionPublica { id; nombre; recargo: number; disponible: boolean }`, `GrupoPublico { id; nombre; min: number; max: number; opciones: OpcionPublica[] }`, `ProductoPublico { id; nombre; descripcion: string | null; precio: number; foto: { chica: string; grande: string } | null; disponible: boolean; etiquetas: string[]; grupos: GrupoPublico[] }`, `CategoriaPublica { id; nombre; enHorario: boolean; horario: { desde: string; hasta: string } | null; productos: ProductoPublico[] }`, `CartaPublica { local: { nombre: string; slug: string; marca: Record<string, unknown> }; categorias: CategoriaPublica[] }`
- `type Seleccion = Record<string /*grupoId*/, string[] /*opcionIds*/>`
- `validarSeleccion(producto: ProductoPublico, sel: Seleccion): { ok: true } | { ok: false; errores: string[] }` — por grupo: cantidad entre `min` y `max`; opciones existentes, disponibles y sin repetir; grupos desconocidos son error.
- `precioUnitario(producto: ProductoPublico, sel: Seleccion): number` — precio + suma de recargos.

- [ ] **Step 1: Tests que fallan**

```ts

expect(formatearPrecio(250050)).toBe('$ 2.500,50');
expect(formatearPrecio(0)).toBe('$ 0');
expect(formatearPrecio(123456789)).toBe('$ 1.234.567,89');

// producto: precio 500000; grupo "Tamaño" min 1 max 1 [Chica +0, Grande +150000];
// grupo "Extras" min 0 max 2 [Cheddar +80000, Bacon +100000, Huevo (no disponible)]
expect(validarSeleccion(p, {})).toEqual({ ok: false, errores: ['Elegí una opción en "Tamaño"'] });
expect(validarSeleccion(p, { tamano: ['grande'] })).toEqual({ ok: true });
expect(validarSeleccion(p, { tamano: ['grande'], extras: ['cheddar', 'bacon', 'cheddar'] }).ok).toBe(false);
expect(validarSeleccion(p, { tamano: ['chica'], extras: ['huevo'] }).ok).toBe(false);
expect(validarSeleccion(p, { tamano: ['chica'], otro: ['x'] }).ok).toBe(false);
expect(precioUnitario(p, { tamano: ['grande'], extras: ['cheddar', 'bacon'] })).toBe(830000);
```

Mensajes exactos: min 1 max 1 → `Elegí una opción en "<grupo>"`; min>1 → `Elegí al menos <min> en "<grupo>"`; exceso → `Podés elegir hasta <max> en "<grupo>"`; opción no disponible → `"<opción>" no está disponible`.
