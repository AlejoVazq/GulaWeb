# Fase 5 — Impresión: Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cada pedido confirmado (QR confirmado o manual/mostrador creado) imprime sus comandas, un ticket por sector con corte, en la térmica USB de 80 mm; reimpresión marcada; ticket de cuenta no fiscal; vista previa en pantalla para la demo sin impresora; nunca se pierde una comanda en silencio.

**Architecture:** Todo en la app de PC, sin servidor. Un modelo de documento serializable (`Documento`: líneas con estilo) se arma con funciones puras a partir de los datos locales y se **maqueta** a un ancho de columnas (48 en 80 mm, 32 en 58 mm). La misma maqueta alimenta al codificador ESC/POS (main) y a la vista previa (renderer). Una **cola de impresión** persistida en SQLite (`impresiones`) guarda cada ticket y su estado; un único trabajador la procesa en orden contra un *transporte*: el de Windows envía bytes RAW al spooler con `WritePrinter` (PowerShell + P/Invoke a `winspool.drv`, sin dependencias nativas); el de vista previa emite el documento al renderer.

**Tech Stack:** el de las fases 1–4. Sin dependencias nuevas (`webContents.getPrintersAsync()` para listar impresoras; PowerShell de Windows para el envío RAW).

**Spec:** `docs/superpowers/specs/2026-11-18-gulaweb-design.md` (§9 paso 6, §10, §12). Base: fases 1–4.

## Global Constraints

- Todas las de las fases 1–4.
- Una impresora para todo; **un ticket por sector** (cocina / barra) con corte de papel; ítems sin sector van a un ticket "GENERAL".
- Comanda: sector, mesa u origen ("MOSTRADOR"), número de pedido, quién atendió, hora, ítems con cantidad, opciones y notas **en grande**; notas del pedido. Reimpresión con la marca `*** REIMPRESIÓN ***`.
- Ticket de cuenta no fiscal con la leyenda exacta **"Documento no válido como factura"**.
- Juego de caracteres CP850 (`ESC t 2`) para ñ, tildes, ¿¡; lo que no exista en CP850 se translitera sin tildes o se reemplaza por `?`.
- 80 mm = 48 columnas (fuente A), 58 mm = 32. Texto doble ancho ocupa el doble.
- Sin impresora configurada, el modo es **vista previa** (la demo funciona de fábrica).
- La impresión nunca bloquea ni hace fallar la confirmación del pedido.
- Estética mínima funcional (fase 10).

## Review Focus

1. **La impresora está apagada, sin papel o desconectada al confirmar** → el pedido queda confirmado igual, el ticket queda "No se imprimió" con el motivo, y un aviso fijo con "Reintentar" no se va hasta reintentar con éxito o descartarlo. → test en Task 4 y Task 6.
2. **La app se cierra (o se cuelga) en medio de una impresión** → al abrir, los tickets que estaban "imprimiendo" quedan como error "No sabemos si salió" (no se reimprimen solos: duplicar una comanda hace cocinar dos veces). → test en Task 4.
3. **Notas con emojis, comillas o caracteres raros, y nombres de producto largos** → se imprimen sin romper el ticket: emoji → `?`, líneas cortadas por palabra al ancho, nada se pierde. → test en Task 1 y Task 2.
4. **Nombre de impresora con comillas o `$`** → el nombre viaja al proceso de impresión por variable de entorno, nunca interpolado en el script. → test en Task 3.
5. **Se confirman dos pedidos seguidos rápido** → los tickets salen en orden y sin entrelazarse (un solo trabajador). → test en Task 4.

### Task 1: Documento, maqueta y ESC/POS

**Files:** Create `apps/desktop/src/compartido/impresion.ts`, `apps/desktop/src/main/impresion/escpos.ts` · Test: `apps/desktop/test/impresion-escpos.test.ts`

**Interfaces — Produces:**
- `type Linea = { tipo: 'texto'; texto: string; alinear?: 'izq' | 'centro' | 'der'; tam?: 'normal' | 'alto' | 'doble'; negrita?: boolean } | { tipo: 'par'; izq: string; der: string; negrita?: boolean; tam?: 'normal' | 'alto' } | { tipo: 'separador' } | { tipo: 'espacio' }`.
- `type Documento = { titulo: string; lineas: Linea[] }`.
- `type Renglon = { texto: string; tam: 'normal' | 'alto' | 'doble'; negrita: boolean; alinear: 'izq' | 'centro' | 'der' }`.
- `maquetar(doc: Documento, columnas: number): Renglon[]` — corta por palabra (palabras más largas que el ancho se parten); `doble` usa `columnas/2`; `par` justifica `der` a la derecha (si no entra, `izq` se corta en renglones y `der` va en el último); `separador` = `-` × ancho.
- `aCp850(texto: string): Uint8Array` y `aEscPos(doc: Documento, columnas: number): Uint8Array` — `ESC @`, `ESC t 2`, por renglón `ESC a n`, `ESC E n`, `GS ! n` (alto `0x01`, doble `0x11`), texto, `LF`; al final 4 `LF` y `GS V 66 0` (avance y corte).

- [ ] **Step 1: Tests que fallan** — `maquetar` de un texto de 60 caracteres a 48 columnas da 2 renglones cortados entre palabras; `doble` a 48 corta a 24; `par('Total', '$ 1.500')` mide exactamente 48 con el monto al final; `aCp850('ñÑáé¿¡')` = `[0xA4,0xA5,0xA0,0x82,0xA8,0xAD]`; `aCp850('pizza 🍕')` termina en `?` y no en bytes multibyte; `aEscPos` empieza con `1B 40 1B 74 02` y termina con `1D 56 42 00`.
- [ ] **Step 2–5** — `feat(desktop): documento de impresión y ESC/POS`

### Task 3: Transporte RAW a impresora de Windows

**Files:** Create `apps/desktop/src/main/impresion/windows.ts` · Test: `apps/desktop/test/impresion-windows.test.ts`

**Interfaces — Produces:**
- `type Transporte = { imprimir(impresora: string, datos: Uint8Array): Promise<void> }`.
- `crearTransporteWindows(opts?: { ejecutar?: Ejecutar; dirTemporal?: string }): Transporte` — escribe los bytes a un archivo temporal, lanza `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command -` con el script por stdin y `GULA_IMPRESORA` / `GULA_ARCHIVO` por **entorno**; el script hace `OpenPrinter` → `StartDocPrinter` (datatype `RAW`) → `WritePrinter` → `EndDocPrinter`; código de salida ≠ 0 → `Error` con el mensaje en castellano del script ("No se encontró la impresora …", "La impresora no aceptó el trabajo"); borra el temporal siempre; timeout 20 s.

- [ ] **Step 1: Tests que fallan** — con un `ejecutar` falso: el nombre `Caja "1" $x` llega intacto en `env.GULA_IMPRESORA` y no aparece en el script; salida 1 con stderr → rechaza con ese mensaje; el temporal no queda. Solo en win32: imprimir a `Impresora-que-no-existe-<uuid>` rechaza con "No se encontró la impresora".
- [ ] **Step 2–5** — `feat(desktop): impresión RAW por el spooler de Windows`

### Task 4: Cola de impresión persistida

**Files:** Modify `apps/desktop/src/main/db/migraciones.ts` (v4) · Create `apps/desktop/src/main/db/impresiones.ts`, `apps/desktop/src/main/impresion/cola.ts` · Test: `apps/desktop/test/impresion-cola.test.ts`

**Interfaces — Produces:**
- Tabla `impresiones(id, tipo 'comanda'|'cuenta'|'prueba'|'cierre', pedido_id null, sector_id null, titulo, documento json, estado 'pendiente'|'imprimiendo'|'impresa'|'error'|'descartada', error null, intentos, creada_en, impresa_en null)`.
- `type ConfigImpresion = { modo: 'impresora' | 'vista_previa'; impresora: string | null; columnas: 48 | 32 }` en `kv` (`impresion:config`); por defecto `{ modo: 'vista_previa', impresora: null, columnas: 48 }`.
- `type TrabajoImpresion = { id; tipo; pedidoId; titulo; estado; error; creadaEn; impresaEn }`.
- `crearColaImpresion({ base, transporte, alVistaPrevia: (doc: Documento, columnas) => void, alCambiar: () => void, ahora? })` → `{ encolar(t: { tipo; pedidoId?; sectorId?; documento }[]): void; reintentar(id): void; descartar(id): void; recuperar(): void; config(): ConfigImpresion; fijarConfig(c): void; trabajos(): { conError: TrabajoImpresion[]; recientes: TrabajoImpresion[] }; esperar(): Promise<void> }`.
  - Un solo trabajador procesa `pendiente` en orden de `id`; marca `imprimiendo` antes de enviar; éxito → `impresa`; fallo → `error` con el mensaje.
  - `vista_previa` llama a `alVistaPrevia` y marca `impresa`. `impresora` sin nombre → `error` "No hay impresora elegida".
  - `recuperar()` (al iniciar): `imprimiendo` → `error` "La app se cerró mientras imprimía: no sabemos si salió."; `pendiente` se procesa.
  - `recientes`: últimos 20.

- [ ] **Step 1: Tests que fallan** — con transporte que falla: el trabajo queda `error` con el mensaje y `conError` lo lista; `reintentar` con transporte sano lo deja `impresa`; dos `encolar` seguidos se envían en orden y nunca en paralelo (transporte lento con contador de concurrencia ≤ 1); `recuperar` pasa `imprimiendo` a `error` sin enviarlo; vista previa llama a `alVistaPrevia` con el documento.
- [ ] **Step 2–5** — `feat(desktop): cola de impresión`
